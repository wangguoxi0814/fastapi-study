## 问题列表

1. **SQLAlchemy 中 `db.add()` 的作用是什么？为什么修改密码时需要用它？**
   > 原问题：这里为什么要这样做（指向 `db.add(user)`）

   关键点：
   - `db.add()` 的语义是"把对象纳入 Session 管理"，不只是添加新记录
   - 新对象 → INSERT（Pending 状态），已有对象 → 追踪变更（UPDATE）
   - 对象处于 Detached（游离）状态时，需要 `db.add()` 重新关联到 Session

2. **为什么 `user.password = hashed_new_pwd` 不会自动被 SQLAlchemy 追踪？**
   > 原问题：不是有这个 user.password = hashed_new_pwd 就会跟踪这是一个被修改了的对象吗

   关键点：
   - 对象在当前活跃 Session 的 Identity Map 中时，SQLAlchemy **会**自动追踪
   - 只有对象处于 Detached（游离）状态时才不会自动追踪
   - `db.add()` 是防御性写法，确保对象在 Session 追踪范围内

3. **`db.add()` 注释掉也能正常更新，为什么？**
   > 原问题：我这里的 add 注释掉了也能正常更新，但是我的 user 来源是依赖项

   关键点：
   - FastAPI 的依赖缓存机制：同一请求中 `Depends(get_db)` 只调用一次
   - `get_current_user` 和 router 共享同一个 Session 实例
   - `user` 始终在同一 Session 的 Identity Map 中，修改自动追踪
   - `get_db()` 的 `yield` 后代码在**整个请求结束后**才执行，不会提前关闭 Session

4. **SQLAlchemy 怎么做事务管理？**
   > 原问题：SQLAlchemy怎么做事务管理

   关键点：
   - Session 就是事务容器，`commit()` 提交、`rollback()` 回滚
   - `flush()`：发送 SQL 到数据库但不提交（可获取自增 ID）
   - `commit()`：提交事务，永久生效
   - `refresh(obj)`：从数据库重新加载对象
   - `expire_on_commit=False`：commit 后对象属性保持原值，不触发重新查询

5. **Expired（过期）和 Detached（游离）有什么区别？**
   > 原问题：expire_on_commit 只是确保 commit 后对象是否可以使用吗

   关键点：
   - **Expired**：仍在 Session 的 Identity Map 中，访问属性时**自动重新查库**
   - **Detached**：不在 Session 中，访问属性**直接报错** `DetachedInstanceError`
   - `expire_on_commit` 只影响 Expired 状态，不会导致 Detached

6. **什么情况下对象会变成游离态？**
   > 原问题：那什么情况下，对象才会处于游离态

   关键点：
   - `session.close()`：Session 关闭，所有对象变游离
   - `session.expunge(obj)`：显式移除单个对象
   - Session 作用域结束（如 `async with` 退出）
   - 对象序列化/反序列化（pickle）

7. **FastAPI 中多个依赖项的执行顺序是什么？**
   > 原问题：这里有多个依赖项，执行顺序是什么

   关键点：
   - 从左到右，深度优先
   - 相同依赖（如 `get_db`）只执行一次，结果缓存共享
   - 执行顺序：解析请求体 → 解析 Header → 创建 Session → 调用认证函数 → 执行路由

8. **`get_db` 的 `finally` 什么时候执行？**
   > 原问题：get_current_user 执行完后，不是会进入依赖项 get_db 的 finally 吗

   关键点：
   - `yield` 依赖的 cleanup（commit/rollback/finally）在**整个请求结束后**才执行
   - 不是 `get_current_user` 返回时执行，而是 router 返回响应后才执行
   - 这保证了整个请求生命周期内 Session 都可用

9. **如何实现旁路缓存装饰器？**
   > 原问题：我要在这里实现一个缓存的装饰器，来修饰 get_categories，实现旁路缓存

   关键点：
   - Cache-Aside 模式：先查缓存 → 命中返回 → 未命中查库 → 写入缓存 → 返回
   - 类装饰器通过 `__call__` 方法实现，返回 async wrapper
   - `@wraps(func)` 保留原函数的元信息（`__name__`、`__doc__` 等）
   - ORM 对象需要序列化后才能存入 Redis（使用 `jsonable_encoder`）

10. **如何让装饰器同时支持同步和异步函数？**
    > 原问题：这个装饰器只能修饰 async 方法，如果既要能够修饰普通方法，又要能够修饰 async 方法，怎么做

    关键点：
    - 使用 `asyncio.iscoroutinefunction(func)` 检测函数类型
    - 异步函数：返回 `async def wrapper`，内部用 `await`
    - 同步函数：返回 `def wrapper`，内部用 `loop.run_until_complete()`

11. **为什么 ORM 对象无法 JSON 序列化？**
    > 原问题：在设置缓存时为什么报：Object of type Category is not JSON serializable

    关键点：
    - SQLAlchemy ORM 对象不是普通 dict，`json.dumps` 无法处理
    - 解决方案：使用 `fastapi.encoders.jsonable_encoder` 转换
    - 或手写 `serialize` 函数，通过 `__table__.columns` 提取字段

12. **如何让缓存 key 支持动态拼接函数参数？**
    > 原问题：我想要在 key 由能够拼接修饰函数参数的能力，怎么做

    关键点：
    - key 支持三种形式：静态字符串、字符串模板（`"key:{offset}:{limit}"`）、函数
    - 使用 `Union[str, Callable[..., str]]` 类型注解
    - `Callable[..., str]` 表示"任意参数，返回 str 的函数"
    - 运行时通过 `callable()` 检测类型，动态生成缓存键
