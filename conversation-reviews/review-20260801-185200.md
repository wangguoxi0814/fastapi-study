### Pydantic 模型字段与别名

1. **Pydantic 模型中字段名与 alias 在 IDE 中报黄色警告的原因及 `populate_by_name=True` 的作用**
   > 原问题：「为什么user_info这里在idea中报黄色警告，改成userInfo就没了」「populate_by_name=True 是干嘛的」

   关键点：
   - `user_info: str = Field(..., alias='userInfo')` 定义了字段名和别名
   - PyCharm 的 Pydantic 插件建议用 alias 构造实例，所以 `user_info` 标黄
   - `populate_by_name=True` 允许同时使用字段名和 alias 构造实例
   - 没有该配置时，只能通过 alias 构造：`UserInfo(userInfo=...)` ✅，`UserInfo(user_info=...)` ❌

2. **Pydantic `Field()` 的 default 参数用法**
   > 原问题：「TypeError: Field() got multiple values for argument 'default'」

   关键点：
   - `Field()` 第一个参数就是 `default`
   - `Field(...)` 表示必填（无默认值），`Field("bearer")` 表示默认值为 "bearer"
   - 不能同时传：`Field(..., default="bearer")` ❌

3. **Pydantic `model_validate()` 方法的作用**
   > 原问题：「UserInfoResponse.model_validate(user)是干嘛的」

   关键点：
   - 从已有对象（如 ORM 模型）验证并转换为 Pydantic 模型实例
   - 等价于 `UserInfoResponse(id=user.id, username=user.username, ...)`，但更简洁
   - 需要 `model_config = ConfigDict(from_attributes=True)` 配置支持

### 全局异常处理

4. **全局异常处理器为什么没有拦截 ZeroDivisionError**
   > 原问题：「为什么我的全局异常处理没有拦截」「还是没有拦截」

   关键点：
   - 根因：`register_error_handlers` 定义为 `async def` 但调用时没加 `await`，函数体未执行
   - 修复：去掉 `async` 改为普通函数（函数内全是同步操作）
   - `__pycache__` 缓存旧字节码，修改后需清除并重启服务器
   - FastAPI 0.136.1 中，`Exception` 和 `500` 处理器被抽到 `ServerErrorMiddleware`，不在 `ExceptionMiddleware` 中
   - `ServerErrorMiddleware` 会先发送响应再重新抛出异常（用于服务器日志记录）
   - **客户端实际收到了正确的 JSON 响应**，终端显示的 traceback 是正常的服务器日志

### Python 基础

5. **`__pycache__` 目录的作用及 IDEA 不显示的原因**
   > 原问题：「pycache是干嘛的」「为什么idea的文件夹中不显示pycache」

   关键点：
   - `__pycache__` 是 Python 自动生成的字节码缓存目录，加速程序启动
   - 文件名格式：`main.cpython-311.pyc`（cpython-311 表示 Python 版本）
   - IDEA 默认将其配置为「排除目录」（Excluded），自动隐藏
   - 如需显示：齿轮图标 → 勾选 "Show Excluded Files"
   - 改了代码但行为没变时，手动清除 `__pycache__` 强制重新编译

### SQLAlchemy ORM 字段别名

6. **`mapped_column` 给字段起别名的作用及查询结果中的字段名**
   > 原问题：「通过mapped_column给orm对象字段起别名是干嘛的」「查询出来的时候，字段是显示别名还是ORM对象字段名呢」

   关键点：
   - 让 Python 属性名和数据库列名可以不同：`user_name: Mapped[str] = mapped_column("username", ...)`
   - Python 代码里始终用属性名 `user_name`，SQL 执行时自动转为数据库列名 `username`
   - ORM 对象查询 → 返回 Python 属性名
   - 原生 SQL / `.mappings()` 查询 → 返回数据库列名

### SQLAlchemy 查询精简字段

7. **SQLAlchemy 如何查询指定字段（精简字段）**
   > 原问题：「Alchemy要查询精简字段怎么做」

   关键点：
   - `db.query(User.id, User.username).all()` — 返回元组列表
   - `select(User.id, User.username)` + `.mappings().all()` — 返回字典列表
   - `load_only(User.id, User.username)` — ORM 层面控制加载的字段，SQL 只查这两列（最省内存）
   - Pydantic 模型转换 — 控制 API 返回格式（全查再过滤）

### SQLAlchemy JOIN 查询

8. **SQLAlchemy 中各类 JOIN 的写法及多条件连接**
   > 原问题：「如果要改成一个联合查询，怎么改」「如果要明确左连接或右连接怎么写，如果连接条件有多个，怎么写」「_and无法导入包」「如果要全外连接呢？」

   关键点：
   - `.join()` 默认 INNER JOIN
   - `.join(..., isouter=True)` 左连接（LEFT JOIN）
   - 交换表顺序 + `isouter=True` 右连接（RIGHT JOIN）
   - `.join(..., full=True)` 全外连接（FULL OUTER JOIN）
   - 多条件：`from sqlalchemy import and_`，然后 `.join(..., and_(条件1, 条件2))`
   - 或用 `&` 运算符：`.join(..., (条件1) & (条件2))`

9. **`select_from` 不是控制连接类型的**
   > 原问题：「我加了select_from，怎么日志打印出来还是inner join」

   关键点：
   - `select_from` 只指定主表是哪个，不控制连接类型
   - 控制连接类型的是 `.join()` 的 `isouter` / `full` 参数
   - `select(User)` 已隐含 `FROM user`，不需要额外写 `select_from(User)`（冗余）
   - `select_from` 的真正用途：`select(func.count()).select_from(User)` — 当 `select()` 里没有表信息时

### LEFT JOIN 中 ON 与 WHERE 的区别

10. **LEFT JOIN 中 ON 条件和 WHERE 条件的区别**
    > 原问题：「LEFT JOIN 的 WHERE 会过滤掉右表为 NULL 的行，这是什么意思」

    关键点：
    - `ON` 里的条件 → 决定**怎么匹配**，匹配不上的保留左表行（右表填 NULL）
    - `WHERE` 里的条件 → 决定**最终保留哪些行**，不满足的直接丢掉
    - LEFT JOIN 时，过滤右表的条件放 `and_()` 里写在 ON 后面，否则等效于变成 INNER JOIN
    - 示例：`.join(Token, and_(User.id == Token.user_id, Token.is_active == True), isouter=True)`

### FastAPI Swagger 文档认证

11. **Swagger Authorize 按钮的配置与使用**
    > 原问题：「这个tokenUrl什么意思」「为什么在Authorize发送login请求后报错」「传进来的token是undefined」「我这里必须要有一个authorization的请求头，但是我又想在docs中使用token」

    关键点：
    - `OAuth2PasswordBearer(tokenUrl="...")` 会自动从 `Authorization: Bearer xxx` 头提取 token
    - `tokenUrl` 仅是 Swagger 文档提示，不影响运行逻辑
    - Swagger Authorize 按钮的内置登录发送的是**表单数据**（`application/x-www-form-urlencoded`），不是 JSON
    - 标准 OAuth2 响应需要 `access_token` 字段，自定义格式会导致 token 为 undefined
    - **正确用法**：先调登录接口拿 token → 点 Authorize 手动粘贴 token → 测试其他接口
    - 需要安装 `python-multipart`：`pip install python-multipart`

12. **前端发送 Authorization 请求头的格式要求**
    > 原问题：「前端传Authorization的请求头充当token，获取不到」

    关键点：
    - 格式必须是 `Authorization: Bearer xxx`（Bearer + 空格 + token）
    - 常见错误：缺少 `Bearer ` 前缀、缺少空格、大小写错误
